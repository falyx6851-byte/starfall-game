# 逐星者 M03：基础包覆候选验收记录

## 1. 交付范围与状态

以 H01 完整 GLB 为稳定底座，只重建网格 `08 Asymmetric shoulder mantle`。其余九个网格的属性和索引字节、节点、骨架层级、逆绑定矩阵、全部原动画通道与关键帧、材质和贴图均保持不变。H01 头盔、肩甲、胸甲、武器、身体、长披风和游戏均未修改。

M03 是实际生成并导出的三维蒙皮 GLB，已在原渲染链路的旋转预览中运行；**没有接入可玩游戏**。本轮没有金边网格、装饰性褶皱、新纹理、新打光、布料物理或新增预览系统。默认启用原有中性灰模。GLB 保留原布料材质槽以便后续接入，并不代表本轮已恢复或验收深青材质。

M02 原始模型、源脚本和报告原样封存在 `backup/`，原 M02 完整 ZIP 与 HTML 保持未动。旧报告里“已经包覆”的结论与实际画面不符，不再沿用。H01 头盔后续待核对的眉额、颧颌与月牙根部简化也仍保留，不在本轮处理。

## 2. 复查 M02：问题不是统一的法线错误

M02 源脚本存在。实际读取后确认：披布在绑定空间中生成，肩甲数据被简化为顶部中央支撑线和边界控制点；没有用完整隆起外表面约束输出，也没有反查原预览 DesignPose 的最终位置。原肩甲主体随 Arm.R（11）刚性变形，而 M02 披布混合 Chest（3）与 Arm.R 权重，因此绑定空间的预计关系不能替代显示姿态中的覆盖关系。

在最终读取的原 M02 资产上，按原动画采样器得到 DesignPose、0 秒后的三角形，再与 Y=1.90 的水平面求交，复现了：

| 对象 | 截面最外侧 X |
|---|---:|
| H01 肩部网格 | -0.51493285 |
| 原 M02 披布 | -0.41162153 |

这侧 X 越负越靠外。M02 在此截面少了约 0.10331 模型单位的外侧覆盖，和用户给出的定位一致。它不是靠整体平移或修法线即可解决的问题。原始五截面记录见 `M02_diagnosis_sections.json`。

## 3. M03 局部建模方法

从 H01 实际肩部网格中按材质与骨骼权重选取披肩侧完整银色外壳及边缘，共 2296 个原有三角形。扣点取自未改动胸甲网格中原金色扣件的背部安装区域，不再用旧披布顶点均值冒充扣件。

先把实际肩甲变形到 DesignPose、0 秒，在这一空间中为完整肩甲构造外包络。基础布面沿包络上方留出间隙，越过外侧支撑后通过连续下摆曲线主要向下延伸。再按披布自己的权重反算回绑定空间，写入 GLB。肩甲和布不需要在绑定时坐标相同，但必须在最终原动画变形后保有预计关系。

覆盖主体使用与肩甲一致的 Arm.R 权重；仅靠近扣点的一小块区域过渡到 Chest，安装点保持 Chest 固定。此举不修改关节、不增加骨骼、不改动画。所有新增几何属于同一个披肩网格，只有原布料材质，没有金边图元。

构造参数、实际支撑三角形、扣件区域、DesignPose 蒙皮矩阵、目标空间和绑定空间顶点分别保存在 `construction.json`、`pauldron_source.npz`、`mantle_authoring.npz`。局部方法是表面包络建模加蒙皮反算，不是将 H01 或 M02 披布整体平移，也不是通过隐藏肩甲达成遮盖。

## 4. 检验最终显示的模型

### 4.1 最终 GLB 的同姿态截面

下列数值来自最终 M03 导出、重新读取、原动作变形后的三角形与水平面求交，不是建模控制点或整件包围盒。

| Y | 未修改肩甲最外侧 X | M03 布面最外侧 X |
|---:|---:|---:|
| 1.80 | -0.57310318 | -0.59357220 |
| 1.85 | -0.54711681 | -0.56308865 |

| 1.94 | -0.47821417 | -0.49883926 |
| 1.96 | -0.44561274 | -0.47488997 |

同一水平面内的最小 X 不能独立证明所有位置的包覆，以下表面检查是补充条件，不用单一截面替代整面验收。原始数值见 `final_sections.json`。

### 4.2 表面覆盖，而非中心线

计划覆盖区选为原肩甲中 DesignPose 三角形中心 Y>=1.86、外法线 Y>0.20 的上部区域，每个三角形取四个固定重心样点，跟随同一骨骼变形后检测。

- 肩顶检查：6564 个样点沿 DesignPose 的 +Y 方向发出射线，此方向随 Arm.R 变形。
- 外侧检查：其中 5020 个外侧样点沿实际外表面法线发出射线；排除朝向内侧颈口的方向（DesignPose 法线 X>0.35），内侧仍由肩顶方向检查，并单列间隙问题。

对 DesignPose、Idle、Run、Attack1 共 23 个姿态/时刻，以上两组样点均在肩甲外侧正距离处命中披布。相同检查用于原 M02 时，静态肩顶仅 197/6564、外侧 224/5020 命中；检查不是仅验证数据有限或动画能播放。

静态外侧间隙约 0.00974～0.03908 模型单位。**内侧扣点跨接并非处处紧贴肩甲**：肩顶方向有 363 个样点间隙超过 0.08，最大约 0.142，集中在内侧抬高过渡范围。因此不声称整片布都只有设定的 0.014 均匀间隙。这一跨接仍需后续外观验收，不用“全部射线命中”掩盖。

本轮初始全法线检查有射线从有意保留的内侧颈口方向逃出，其诊断保留在 `pass1_coverage_M03.json` 和 `development/`。最终将“肩顶遮盖”和“外侧包覆”作为两个明确的几何问题分别检查；没有把原失败计数改写成同一测试通过。

全部时间、采样区定义、方向、距离和结果见 `directional_coverage_M03.json`；M02 对照见 `directional_coverage_M02.json`。这是离散采样，不证明所有连续位置、所有相机和任意时刻都无孔洞或穿插。

### 4.3 下垂方向

沿最终显示网格的三个外侧剖面，自支撑末端到自由边缘，向下变化约 0.145～0.182，水平变化约 0.065～0.072；向下/水平比约 2.02～2.75。测量只描述这三个实际剖面，和侧面实机图共同判断下垂，不作为全局布料物理结论。

### 4.4 核对真实渲染器的蒙皮结果

采用原 H01 顶点着色器原文，用 WebGL transform feedback 读取同一导出网格经过实际 GPU 蒙皮后的世界坐标。DesignPose/0、Run/0.34、Attack1/0.13、0.16、0.32 共五个姿态，每姿态 513 个抽样顶点；与检查脚本的计算偏差均小于 0.000001 模型单位。原 Animator 骨骼矩阵也核对一致。

该测试没有把新着色器接入预览，也没有仅根据动画名称判断正确。测试装置只采集原着色器输出；最终 HTML 的渲染器和原 H01 字节一致。详见 `gpu_verification.json`。

## 5. 动作问题定位与当前限制

早期 M03 候选在 **Attack1、0.16 秒、披肩侧面与后侧**，扣点向肩甲过渡的布面与原肩甲产生了 64 对非共面三角形交叉。位置记录保留在 `development/pass1_intersections.json`，初始源文件保留在 `development/build_pass1.py`。

原因是局部曲面规则在抬高的颈侧边界处切换不连续，且 Chest 权重影响范围跨入肩甲主体。已将边界轮廓连续过渡，并把 Chest 权重集中在更靠近扣点的范围。修改限于披肩几何/权重，没有移动肩甲或重写原动作。

最终资产对肩甲银色外壳和蓝钢下层甲片进行了 **16 个姿态/时刻的非共面三角形交叉检查，未检测到交叉**。安装点相对原胸前固定点的误差约 0.00000003 模型单位。具体时间和范围见 `surface_intersections.json`。

| 动作与时间 | 实际检查机位 | 当前观察 |
|---|---|---|
| DesignPose / 0 | 正面、披肩侧面、三分之四、略俯视、背侧、全身 | 上部甲壳已被基础布面覆盖，下层甲片和上臂可露出。内侧跨接仍略高。 |
| Idle / 0；数值抽查另含 1.2 | 三分之四近景 | 扣点保持连接，主体覆盖未缩回肩甲内侧。 |
| Run / 0.34；数值检查覆盖更多采样时刻 | 三分之四、披肩侧面 | 布面跟随肩部，覆盖维持；动态仍偏硬，没有物理垂坠。 |
| Attack1 / 0.13 | 三分之四近景 | 抬臂时布面整体随上臂抬起，刚性感明显，不能称为自然布料动作。 |
| Attack1 / 0.16 | 三分之四、侧面、后侧 | 已修正早期候选的局部交叉；自由下摆仍有整片上翻/抬起感。 |
| Attack1 / 0.32 | 三分之四近景 | 外壳上部覆盖维持，下方原层叠甲片可见；不代表整套动作已经定稿。 |

数值交叉测试排除了共面接触、其他身体部位、披布自交与任意未采样时刻。没有宣称全动作逐帧零穿插；也没有把“没有数值异常”当作外观通过。动作截图见 `sheets/Stargazer_M03_POSES.jpg`，原图在 `final/M03/`。

## 6. 截图条件

三版共用 1500×1120、DPR=1、原中性棚光、原灰模响应与 2048 阴影。对照的九个共同视图逐值核对相机矩阵、眼点、姿态时间、显示尺寸、画质和灰模开关一致。没有单独放大 M03、改变肩甲尺寸或调亮新版。

全部为实际 WebGL 截图。拍摄夹具暂停自动时钟，调用原 Animator 和 draw；没有替换成静态图片。近景、全身和战斗机位使用同一个 GLB 哈希。拼图仅裁切与排版，各版采用相同裁切框和缩放。`comparison_conditions.json` 和各版 `final/*/capture.json` 保留拍摄参数。

战斗机位是在独立验收宿主中复现原 v0.1.3 相机、场景与角色显示缩放，不是已经安装到可玩游戏中的截图。本轮没有加载新的战斗控制器。
